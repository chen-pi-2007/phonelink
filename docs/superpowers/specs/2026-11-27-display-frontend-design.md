# 副屏新界面设计（2026-11-27）

## 为什么做

副屏装在电动车车把上，骑车时只能瞥一眼。现在的界面能用但很简陋。用户希望它像电脑上的 Mineradio 一样有沉浸感（发光歌词、粒子律动、流动背景），同时把导航融合进来。每一次状态切换都要有过渡动画，动画照搬市面成熟 App 的做法，不自己发明。

## 目标

1. **音乐页**：封面取色的流动背景、封面卡片、逐行滚动歌词（有逐字歌词时逐字点亮）、随音乐律动的粒子。
2. **导航页**：转向箭头、距离、下一条路名、剩余里程和时间，和主手机的高德、百度、腾讯地图同步。
3. **手势**：上下滑切换音乐页和导航页；左右滑切换上一首和下一首。
4. **导航插播**：停在音乐页时，快到路口会从顶部滑下导航提示条，过了路口自动收起。
5. **所有状态切换都有过渡动画**：切歌、换行、播放/暂停、翻页、导航开始和结束、连接和断开。

## 不做（这一版）

- 播放器诊断和歌单浏览（用户已明确暂缓）
- 录屏式音频捕获（实测系统频谱接口就够用，不需要它）

## 反目标（技术上能跑，但出现就算失败）

- 骑车时看不清：歌词和导航文字必须在户外阳光下一眼可读，特效永远不能盖住文字。
- 晃眼、分散注意力：律动只做柔和的脉冲和发光，不能大面积闪烁。
- 明显更耗电：渲染上限 30 帧，副屏 App 不在前台时停止渲染；主手机只在“已连接 + 正在播放”时才算律动。

## 方案选择

| 方案 | 取舍 | 结论 |
|---|---|---|
| **A. 网页技术做界面**（副屏 App 内嵌 WebView） | 特效写法成熟，改起来快；能先在电脑浏览器里看样稿再装机；代价是比原生多一点耗电 | **采用**（用户授权由我来选） |
| B. Jetpack Compose 原生重写 | 性能最好；但要引入 Kotlin 和 AndroidX，每改一版都要装机才能看，设计来回成本高 | 不选 |
| C. 现有原生控件上补动画 | 特效最难做；安卓 11 没有系统模糊 | 不选 |

## 已确定的做法

### 副屏
- `DisplayActivity` 改成全屏 WebView，加载 App 内置的 `assets/ui/index.html`，用原生 JavaScript 加 Canvas 2D，不引入前端框架，以控制体积。
- 数据从原生传给网页：调用 `window.pl.onMessage(json)`，主手机发来的 state、lyrics、beat、nav 消息原样转交。
- 命令从网页传回原生：通过 JavaScript 接口发送 toggle、next、prev、seek 等命令。
- 蓝牙连接、自动更新、保活逻辑全部保持不变，只替换显示层。
- 网页在浏览器里打开时自动进入“演示模式”，用假数据驱动，用来出样稿和调界面。

### 主手机
- **歌词**：用歌名加歌手去网易云的公开接口搜歌，优先取逐字歌词（yrc），没有就取逐行歌词（lrc）和翻译。按歌缓存，每首歌只给副屏发一次完整歌词，副屏按播放进度自己对时间。搜不到时退回“车载蓝牙歌词”字段，听书就显示章节名。
- **律动**：用系统频谱接口（Visualizer，session 0）算音量能量和节拍起点，每秒约 30 次发给副屏。只在“副屏已连接 + 正在播放 + 播放的 App 在白名单里”时运行。拿不到数据时，副屏改用歌词时间轴驱动脉冲。

### 动画参照（照搬成熟 App）
| 场景 | 参照 |
|---|---|
| 左右滑切歌：封面跟手，过半松手切换，不过半弹回 | Apple Music、Spotify 的迷你播放条 |
| 歌词滚动：当前行放大发光，其余行变暗并轻微模糊，弹性滚动 | Apple Music 的歌词页 |
| 逐字点亮 | Apple Music、网易云的逐字歌词 |
| 流动渐变背景，换歌时颜色平滑过渡 | Apple Music 的全屏播放页 |
| 上下滑整页切换 | 抖音的竖向翻页 |
| 导航插播提示条从顶部滑下 | iOS 实时活动 / 灵动岛的展开动画 |
| 播放和暂停按钮变形 | Material Design 的图标变形动画 |
| 连接中的占位效果 | 骨架屏微光（shimmer） |

## 留给实现时决定的

- 具体颜色、字号、动画时长和缓动曲线（先出样稿让用户看，再调）
- 粒子数量和律动强度的具体参数

## 风险

- 网易云接口是非官方的，可能变动或限流。歌词获取要做成可替换的模块，失败时有退路。
- 主手机戴蓝牙耳机时，频谱接口能不能拿到数据还没验证，要在主手机上实测。
- 副屏是 2018 年的骁龙 845，WebView 跑 30 帧粒子应该没问题，以装机实测为准。

## 交付顺序

1. 浏览器里能点的样稿（假数据），用户确认视觉和手感
2. 装进副屏，接入真实数据
3. 主手机：歌词获取和律动数据
4. 导航页和导航插播（拿到导航诊断记录后做精）
